## 1. Python 基础语义

### Q1：Python 是解释型语言吗？这句话准确吗？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐（8星）**

**答案：**

通常会说 Python 是解释型语言，但更准确一点的说法是：

- Python 源码先被编译成字节码
- 再由解释器（如 CPython 的虚拟机）执行

所以它不是“逐行直接解释源码”，而是：

> `源码 -> 字节码 -> 虚拟机执行`

**面试可讲一句话：**

“Python 一般被归为解释型语言，但运行时通常会先编译成字节码，再由解释器执行。”

---

### Q2：Python 的 list 和 tuple 有什么区别？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐（8星）**

**答案：**

核心区别：

- `list` 可变
- `tuple` 不可变

进一步可以讲：

- `tuple` 更适合表达不会变的结构化数据
- `tuple` 一般比 `list` 更轻一点
- 不可变对象更容易作为字典 key 或集合元素使用

**面试可讲一句话：**

“`list` 更适合做动态集合，`tuple` 更适合表达固定结构和值语义更稳定的数据。”

---

### Q3：`is` 和 `==` 的区别是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

- `==` 比较的是值是否相等
- `is` 比较的是两个变量是否引用同一个对象

例子：

```python
a = [1, 2]
b = [1, 2]

a == b   # True
a is b   # False
```

**面试可讲一句话：**

“`==` 看值，`is` 看对象身份。”

## 2. 拷贝、可变对象与参数传递

### Q4：浅拷贝和深拷贝的区别是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

浅拷贝：

- 只复制最外层对象
- 内层嵌套对象还是共享引用

深拷贝：

- 递归复制整个对象结构
- 内层对象也会新建

例子：

```python
import copy

a = [[1, 2], [3, 4]]
b = copy.copy(a)
c = copy.deepcopy(a)
```

如果修改 `a[0][0]`：

- `b` 会受影响
- `c` 不会受影响

**面试可讲一句话：**

“浅拷贝复制壳，深拷贝复制整棵对象树。”

---

### Q5：Python 参数传递是值传递还是引用传递？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

都不完全准确，更合适的说法是：

> Python 传递的是“对象引用的绑定”

函数拿到的是对象引用的副本，但它指向的仍是同一个对象。

所以：

- 如果对象是可变的，函数内部修改对象内容，外部能看到变化
- 如果在函数内部重新绑定变量，不会影响外部绑定

---

### Q6：为什么不要把可变对象写成默认参数？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

因为默认参数在函数定义时只初始化一次。

例如：

```python
def append_item(x, items=[]):
    items.append(x)
    return items
```

多次调用会共享同一个 `items`。

正确写法：

```python
def append_item(x, items=None):
    if items is None:
        items = []
    items.append(x)
    return items
```

## 3. 迭代器、生成器与装饰器

### Q7：什么是迭代器？

**掌握程度：⭐⭐⭐⭐（8星）**  
**考察频次：⭐⭐⭐⭐（7星）**

**答案：**

迭代器是实现了：

- `__iter__()`
- `__next__()`

协议的对象。

它可以被 `for` 循环逐个取值，直到抛出 `StopIteration`。

---

### Q8：什么是生成器？和普通函数有什么区别？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

只要函数里出现 `yield`，它就不是普通函数，而是生成器函数。

区别：

- 普通函数一次返回结果
- 生成器按需逐步产出结果

优点：

- 节省内存
- 适合流式处理
- 适合长序列或增量消费

**和 AI 应用的关系：**

生成器思想和流式输出很接近，特别适合做 token/chunk 增量返回。

---

### Q9：什么是装饰器？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

装饰器本质上是：

> 接收一个函数，返回一个增强后函数的高阶函数

常见用途：

- 日志
- 计时
- 权限校验
- 重试
- 缓存

简单示例：

```python
def log_decorator(func):
    def wrapper(*args, **kwargs):
        print("start")
        result = func(*args, **kwargs)
        print("end")
        return result
    return wrapper
```

## 4. 上下文管理器与常见语法点

### Q10：什么是上下文管理器？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

上下文管理器用于管理资源的进入和退出。

常见形式：

- 实现 `__enter__` 和 `__exit__`
- 使用 `contextlib.contextmanager`

最典型场景：

- 文件打开关闭
- 数据库连接
- 锁的获取与释放

**一句话表达：**

“上下文管理器的核心价值是把资源申请和清理包在同一个语义块里。”

- `**kwargs` 收集关键字参数

## 5. 并发与异步

### Q12：Python 的线程、进程、协程分别适合什么场景？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

线程：

- 适合 I/O 密集型任务
- 编程模型相对直接

进程：

- 适合 CPU 密集型任务
- 可以绕开 GIL

协程：

- 适合高并发 I/O 场景
- 特别适合网络服务、请求编排、异步调用

**面试可讲一句话：**

“I/O 密集型优先考虑线程或协程，CPU 密集型优先考虑多进程。”

---

### Q13：什么是 `asyncio`？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

`asyncio` 是 Python 标准库里的异步 I/O 框架，核心是：

- 事件循环
- 协程
- `await`
- 异步任务调度

它非常适合：

- 并发网络请求
- 调用多个外部服务
- Agent 编排链路中的异步任务执行

---

### Q14：协程为什么适合 Agent 应用开发？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

因为 Agent 平台里很多任务都偏：

- I/O 密集
- 多外部依赖
- 多步调用
- 需要高并发但不一定重 CPU

例如：

- 调 LLM
- 调工具
- 查知识库
- 查数据库
- 请求多个外部服务

这类场景很适合用协程提升吞吐和资源利用率。

## 6. GIL 与性能

### Q15：什么是 GIL？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

GIL 是 CPython 的全局解释器锁。

它意味着：

- 同一个进程里，同一时刻通常只有一个线程执行 Python 字节码

所以：

- Python 多线程不适合纯 CPU 密集型加速
- 但对 I/O 密集型任务仍然有价值

---

### Q16：有了 GIL，为什么 Python 多线程在 I/O 场景仍然有用？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

因为线程在等待 I/O 时会释放执行机会。

所以：

- 网络请求
- 文件读写
- 数据库访问

这类任务里，多线程仍然可以提高并发效率。

## 7. 内存管理与垃圾回收

### Q17：Python 的内存管理主要靠什么？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐（7星）**

**答案：**

Python 内存管理主要依赖：

- 引用计数
- 垃圾回收器（处理循环引用）

简单理解：

- 大多数对象靠引用计数快速释放
- 有循环引用时，再由 GC 做补充清理

---

### Q18：为什么只有引用计数还不够？

**掌握程度：⭐⭐⭐⭐⭐（8星）**  
**考察频次：⭐⭐⭐⭐（7星）**

**答案：**

因为循环引用会导致引用计数无法归零。

例如：

- 对象 A 引用对象 B
- 对象 B 又引用对象 A

即使它们外部都不再可达，引用计数也可能不为 0，所以需要 GC 额外处理。

## 8. FastAPI 与工程实践

### Q19：为什么 FastAPI 很适合 AI 应用研发？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

因为它具备几个非常适合 AI 服务的特征：

- 基于异步能力，适合高并发 I/O
- 类型注解友好
- 自动生成 OpenAPI 文档
- 开发效率高
- 和 Python 生态集成自然

特别适合：

- 模型服务封装
- Agent 服务编排
- 评测服务
- 工具服务

---

### Q20：FastAPI 里同步函数和异步函数怎么选？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

如果你的处理逻辑里有大量异步 I/O：

- 优先 `async def`

如果逻辑本身主要是同步代码或 CPU 重任务：

- 不要盲目都写成异步

核心不是语法，而是：

> 看调用链是否是异步友好的
