## 1. 用户态和内核态

### Q1：用户态和内核态的区别？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（10星）**

**答案：**

**运行模式对比：**
是CPU的两种运行模式，分别为用户态和内核态。
用户态是CPU运行用户态程序的模式，内核态是CPU运行内核态程序的模式。
| 模式 | 权限 | 可执行操作 |
|------|------|-----------|
| **内核态** | 高权限 | 执行所有指令，访问所有硬件资源 |内核程序运行在内核态，具有高权限。
| **用户态** | 低权限 | 执行部分指令，无法直接访问硬件资源 |用户态程序运行在用户态，具有低权限。

**内核态的核心操作：**
- 内存管理
- 进程管理
- 设备驱动程序控制
- 系统调用

**划分的三大原因：**

1. **稳定性**：用户态程序崩溃不影响整个系统
2. **隔离性**：内核与用户程序有明确边界
3. **安全性**：保护系统核心资源和数据安全
用户态和内核态切换：
内核态2用户态切换：
执行特权指令，改变寄存器状态
用户态2内核态，
只需要通过系统调用触发中断即可。
- 系统调用：用户态程序通过系统调用请求内核态执行特权操作
- 中断：硬件异常或外部事件触发内核态处理
- 异常：程序运行时发生的错误，触发内核态处理
以系统调用为例，用户态执行 syscall 指令后，CPU 会切换到内核态并切到该线程的内核栈，保存部分寄存器/返回地址等现场，跳转到内核的系统调用入口；内核完成处理后恢复现场，通过 sysret/iret 之类的返回指令降权回用户态，继续执行下一条用户指令。
缺页异常为什么不是中断？
- 缺页异常是同步的，由CPU访问无效地址触发
- 中断是异步的，由外部设备触发

## 2. 进程管理

### Q2：线程和进程的区别是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（10星）**

**答案：**

| 维度 | 进程 | 线程 |
|------|------|------|
| **本质定义** | 资源分配的基本单位 | 任务调度和执行的基本单位 |
| **开销** | 较大（有独立代码和数据空间） | 较小（共享进程资源） |
| **稳定性** | 线程崩溃可能导致整个进程崩溃 | 子进程崩溃不影响其他进程 |
| **内存分配** | 系统为每个进程分配独立内存空间 | 线程共享所属进程的内存空间 |
| **切换开销** | 大（需保存和恢复整个进程状态） | 小（只需保存线程上下文） |
| **通信方式** | 管道、消息队列等 | 直接读写共享内存 |

### Q3：进程、线程、协程的区别是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

| 维度 | 进程 | 线程 | 协程 |
|------|------|------|------|
| **定义** | 资源分配的基本单位 | CPU调度的基本单位 | 用户态轻量级线程 |
| **内存空间** | 独立内存空间 | 共享进程内存空间 | 共享堆，独立栈和寄存器 |
| **切换开销** | 最大（需切换地址空间） | 较小（只需切换上下文） | 最小（用户态切换） |
| **调度** | 内核调度 | 内核调度 | 用户程序控制 |
| **通信** | 需IPC机制 | 直接共享内存 | 直接共享内存 |
| **稳定性** | 高 | 中（线程崩溃影响进程） | 高（单个协程崩溃不影响其他） |
| **并发数** | 有限（受资源限制） | 有限（受CPU限制） | 可达数万（占用资源少） |

### Q4：为什么进程崩溃不会对其他进程产生很大影响？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐⭐（7星）**

**答案：**

**两大原因：**

1. **进程隔离性**
   - 每个进程有独立的内存空间
   - 崩溃进程的内存空间由操作系统回收
   - 不影响其他进程的内存空间

2. **进程独立性**
   - 进程之间不共享资源（文件、网络连接等）
   - 一个进程的崩溃不会导致其他进程的资源泄漏

**底层保障：** 操作系统通过虚拟内存机制实现进程隔离

### Q6：讲下为什么进程之下还要设计线程？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**以视频播放器为例：**

**单进程的问题：**
```
Read() → Decompress() → Play()
```
- CPU能力不足时，Read阻塞导致整个播放器卡顿
- 各函数无法并发执行，资源利用率低

**多进程的问题：**
- 进程间通信复杂（需管道、消息队列等）
- 系统开销大（创建/切换进程需要分配资源）

**线程的优势：**
- 线程间可以并发运行
- 线程间共享地址空间，通信高效
- 系统开销小（线程切换无需切换地址空间）

**核心需求：**
1. 实体之间可以并发运行
2. 实体之间共享相同的地址空间

### Q7：多线程比单线程的优势，劣势？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**优势：**

| 优势 | 说明 |
|------|------|
| **提高效率** | 充分利用多核处理器资源 |
| **并发处理** | 同时处理多个任务 |
| **响应速度** | 提高程序响应能力 |

**劣势：**

| 劣势 | 说明 |
|------|------|
| **数据竞争** | 多线程访问共享数据需要同步 |
| **死锁风险** | 锁使用不当可能导致死锁 |
| **资源消耗** | 每个线程占用内存和处理时间 |
| **复杂度增加** | 编程和调试难度增加 |

### Q8：多线程是不是越多越好？太多会有什么问题？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**不是越多越好，存在的问题：**

**1. 切换开销问题**
- 线程创建和切换消耗系统资源
- 线程过多导致系统负载过高
- CPU时间浪费在上下文切换

**2. 死锁和竞争问题**
- 多线程竞争共享资源导致数据不一致
- 死锁风险增加

**3. 稳定性问题**
- 某个线程崩溃可能导致整个进程崩溃

**最佳实践：**
- 根据CPU核心数合理设置线程数
- 避免创建过多线程
- 使用线程池管理线程

### Q9：进程切换和线程切换的区别？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

| 维度 | 进程切换 | 线程切换 |
|------|---------|---------|
| **切换内容** | 整个进程的地址空间、全局变量、文件描述符等 | 线程的堆栈、寄存器、程序计数器 |
| **开销大小** | 较大 | 较小 |
| **涉及资源** | 虚拟内存、内核堆栈、全局变量、寄存器 | 线程堆栈、程序计数器 |
| **TCB/PCB** | 进程控制块PCB | 线程控制块TCB |

**核心区别：** 线程切换不需要切换地址空间

### Q10：线程切换为什么比进程切换快？节省了什么资源？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**节省的资源：**

1. **地址空间**
   - 线程共享进程地址空间，无需切换页表
   - 进程切换需要切换内存映射表

2. **内存资源**
   - 线程共享全局变量和堆
   - 进程需要独立的内存空间

3. **内核资源**
   - 线程共享文件描述符等内核资源
   - 进程需要独立维护这些资源

**核心原因：** 线程在同一进程内，共享大部分资源

### Q11：线程切换的详细过程是怎样的？上下文保存在哪里？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**切换过程（4个步骤）：**

```
1. 上下文保存
   ↓
2. 切换到调度器
   ↓
3. 上下文恢复（选择新线程）
   ↓
4. 切换到新线程执行
```

**上下文保存内容：**
- 寄存器状态
- 程序计数器（PC）
- 堆栈指针

**上下文保存位置：**
- 保存在线程控制块（TCB）中
- TCB是操作系统管理线程的数据结构
- 包含线程状态、寄存器值、堆栈信息

### Q12：进程有哪些状态？如何切换？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**五种状态：**

```
┌─────────────────────────────────────────────────────┐
│  NULL → 创建状态 → 就绪状态 → 运行状态 → 结束状态  │
│              ↑         ↓         ↓                  │
│              └──── ← 阻塞状态 ←─┘                  │
└─────────────────────────────────────────────────────┘
```

**状态切换：**

| 切换路径 | 触发条件 |
|---------|---------|
| NULL → 创建状态 | 新进程被创建 |
| 创建状态 → 就绪状态 | 进程初始化完成 |
| 就绪状态 → 运行状态 | 进程调度器选中 |
| 运行状态 → 就绪状态 | 时间片用完 |
| 运行状态 → 阻塞状态 | 等待I/O或事件 |
| 阻塞状态 → 就绪状态 | 等待的事件完成 |
| 运行状态 → 结束状态 | 进程完成或出错 |

### Q13：进程上下文有哪些？CPU上下文切换是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**CPU上下文：**
- CPU寄存器
- 程序计数器（PC）

**进程上下文切换（切换的内容）：**

| 资源类型 | 具体内容 |
|---------|---------|
| **用户空间** | 虚拟内存、栈、全局变量 |
| **内核空间** | 内核堆栈、寄存器 |
| **控制信息** | PCB（进程控制块） |

**CPU上下文切换步骤：**
1. 保存当前任务的CPU上下文
2. 加载新任务的上下文
3. 跳转到程序计数器指定位置运行

### Q14：进程的上下文切换到底是切换什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**核心切换内容：**

**1. 用户空间资源**
- 虚拟内存地址空间
- 全局变量
- 打开的文件描述符

**2. 内核空间资源**

## 3. 进程间通信

### Q15：进程间通信有哪些方式？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**6种主要方式：**

| 方式 | 特点 | 适用场景 |
|------|------|---------|
| **管道** | 简单、单向、有亲缘关系 | 父子进程通信 |
| **命名管道** | 突破亲缘限制、无关联进程通信 | 任意进程通信 |
| **消息队列** | 消息体自定义、有格式 | 需区分消息类型的场景 |
| **共享内存** | 最快（无需拷贝）、需同步 | 高频数据交换 |
| **信号量** | 控制资源访问次数、实现同步 | 资源计数控制 |
| **Socket** | 跨主机通信 | 网络通信 |

### Q18：共享内存是怎么实现的？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐⭐（6星）**

**答案：**

**实现原理：**

1. 拿出一块虚拟地址空间
2. 映射到相同的物理内存
3. 多个进程可以访问同一块物理内存

**优势：**
- 最快的进程间通信方式
- 无需数据拷贝
- 直接访问共享内存

**问题：**
- 多进程竞争需要同步
- 为什么要同步？是因为多个进程同时访问共享内存，可能会导致数据不一致的问题。
- 需配合信号量等机制实现互斥

## 4. 锁

### Q20：为什么并发执行线程要加锁？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**核心原因：防止竞态条件（Race Condition）**

**竞态条件定义：** 多个线程同时访问共享数据，至少一个线程在写数据

**加锁的作用：**
- 确保同一时刻只有一个线程访问共享数据
- 保证数据的一致性和完整性
- 防止数据损坏

**不加锁的后果：**
- 数据竞争
- 数据不一致
- 程序行为不可预测

---

### Q21：自旋锁是什么？应用在哪些场景？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**定义：** 加锁失败后，线程会"忙等待"，直到拿到锁

**实现原理：**
- 使用CAS函数（Compare And Swap）
- 在用户态完成加锁解锁
- 不会主动产生线程上下文切换

**应用场景：**

| 场景 | 原因 |
|------|------|
| **短临界区** | 临界区执行时间短 |
| **多核系统** | 避免线程切换开销 |
| **用户态切换** | 协程、异步编程 |
| **单核禁用** | 需要抢占式调度器 |

**与互斥锁对比：**
- 互斥锁：加锁失败→线程切换→阻塞
- 自旋锁：加锁失败→忙等待→直到成功

### Q22：死锁发生条件是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**四个必要条件（同时满足才会死锁）：**

| 条件 | 说明 | 示例 |
|------|------|------|
| **互斥条件** | 资源不能被共享，只能互斥使用 | 打印机只能一个用 |
| **持有并等待** | 持有资源同时等待其他资源 | 拿了A还想要B |
| **不可剥夺** | 资源使用完前不能被强制拿走 | 只能自己释放 |
| **环路等待** | 形成资源请求环形链 | A等B，B等A |

### Q23：如何避免死锁？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**最常用方法：资源有序分配法（破坏环路等待条件）**

**原理：** 线程获取资源的顺序必须一致

**示例：**
```
线程A：先获取资源1 → 再获取资源2
线程B：先获取资源1 → 再获取资源2
```

**其他方法：**
- 破坏互斥条件（不太可行）
- 破坏持有并等待（一次性申请所有资源）
- 破坏不可剥夺（允许强制剥夺）
- 银行家算法（预分配资源）

### Q24：讲一下银行家算法

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐（4星）**

**答案：**

**核心思想：** 在分配资源前先判断安全性

**安全性判断：**
- 检查分配后是否会产生死锁
- 寻找安全序列（所有进程都能完成）

**银行家算法的业务逻辑：**

1. **不负荷原则：** 进程最大需求不超过系统总资源
2. **可分期：** 资源可分期请求，总请求不超过最大值
3. **推迟分配：** 资源不足时延迟分配，但保证有限时间内完成

**算法步骤：**
1. 计算当前剩余可用资源
2. 找出能满足最大需求的进程
3. 分配资源给该进程执行
4. 进程完成后释放资源
5. 重复步骤2-4，检查是否能完成所有进程

**安全序列示例：** P2 → P4 → P5 → P1 → P3

### Q25：乐观锁和悲观锁有什么区别？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**悲观锁：**

| 特点 | 说明 |
|------|------|
| **假设** | 冲突频繁发生 |
| **策略** | 读取时加锁，防止修改 |
| **实现** | 数据库行锁、互斥锁 |
| **适用** | 写多场景 |

**乐观锁：**

| 特点 | 说明 |
|------|------|
| **假设** | 冲突很少发生 |
| **策略** | 更新时检查版本 |
| **实现** | 版本号、时间戳、CAS |
| **适用** | 读多写少场景 |

**对比总结：**
```
悲观锁：先加锁，再操作（安全但效率低）
乐观锁：先操作，再检查（效率高但需处理冲突）
```

### Q26：除了互斥锁你还知道什么锁？分别应用于什么场景？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

| 锁类型 | 特点 | 适用场景 |
|--------|------|---------|
| **读写锁** | 多读单写 | 读多写少（如缓存） |
| **自旋锁** | 忙等待 | 短临界区、用户态 |
| **条件变量** | 等待-唤醒 | 线程同步（生产者-消费者） |
| **信号量** | 控制资源数量 | 资源池管理、限流 |

**详细说明：**

1. **读写锁**
   - 读锁：共享，多个线程可同时读
   - 写锁：独占，只允许一个线程写
   - 读多写少场景效率高

2. **自旋锁**
   - 适用于临界区很小
   - 避免线程切换开销
   - 单核需要抢占式调度器

3. **条件变量**
   - 与互斥锁配合使用
   - 实现"等待-通知"机制
   - 用于线程同步

## 5. 进程调度

### Q27：进程调度算法有哪些？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**5种主要算法：**

| 算法 | 特点 | 优缺点 |
|------|------|--------|
| **FCFS（先来先服务）** | 按到达顺序 | 公平，但对短作业不友好 |
| **SJF（最短作业优先）** | 选择运行时间最短的 | 提高吞吐量，但对长作业不友好 |
| **高响应比优先** | 综合等待时间和运行时间 | 兼顾长短作业 |
| **时间片轮转** | 每个进程分配时间片 | 公平，响应时间短 |
| **最高优先级** | 选择优先级最高的 | 可实现优先级调度 |
| **多级反馈队列** | 多级队列+时间片+反馈 | 综合性能最好 |

### Q28：讲一下各种调度算法的原理？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**1. FCFS（先来先服务）**
```
原理：按到达顺序选择进程运行
缺点：长作业会导致短作业等待时间长
```

**2. SJF（最短作业优先）**
```
原理：选择运行时间最短的进程
缺点：长作业可能永远得不到运行
```

**3. 高响应比优先**
```
公式：响应比 = (等待时间 + 运行时间) / 运行时间
优点：短作业和长作业都能兼顾
```

**4. 时间片轮转**
```
原理：每个进程分配固定时间片（20-50ms）
优点：公平性好，响应时间短
```

**5. 最高优先级**
```
原理：选择优先级最高的进程运行
分类：静态优先级（不变）、动态优先级（可调整）
```

**6. 多级反馈队列**
```
特点：
- 多级队列，优先级从高到低
- 优先级越高，时间片越短
- 新进程从最高优先级开始
- 被抢占则降到低优先级队列
优点：兼顾长短作业，性能最优
```

## 6. 内存管理

### Q29：介绍一下操作系统内存管理？

**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**虚拟内存带来的好处：**

| 好处 | 说明 |
|------|------|
| **超越物理内存** | 程序可使用超过物理内存大小的空间 |
| **进程隔离** | 每个进程有独立的虚拟地址空间 |

- **分页机制：** 4KB为一页

**工作流程：**
1. 程序访问虚拟地址
2. MMU通过页表查找物理地址
3. 如果缺页，触发缺页异常
4. 操作系统分配物理内存，更新页表
5. 程序继续执行

### Q30：什么是虚拟内存和物理内存？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**虚拟内存：**

| 特点 | 说明 |
|------|------|
| **定义** | 操作系统提供给每个程序的地址空间 |
| **大小** | 可远大于物理内存 |
| **作用** | 隔离进程、扩展可用内存 |

**物理内存：**

| 特点 | 说明 |
|------|------|
| **定义** | 计算机实际的硬件内存 |
| **大小** | 有限的硬件资源 |
| **作用** | 存储程序运行时的数据 |

**两者关系：**
- 虚拟内存通过页表映射到物理内存
- 虚拟地址空间是连续的，物理地址可以离散

### Q31：讲一下页表？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**页表的作用：** 虚拟地址与物理地址之间的映射

**分页机制：**
- 页大小：Linux下为4KB
- 虚拟地址 = 页号 + 页内偏移
- 物理地址 = 物理页号 + 页内偏移

**地址转换步骤：**
```
1. 虚拟地址 → 页号 + 页内偏移
2. 页号 → 页表查找 → 物理页号
3. 物理页号 + 页内偏移 → 物理地址
```

**页表的特点：**

| 特点 | 说明 |
|------|------|
| **存储位置** | 内存中 |
| **管理单元** | MMU（内存管理单元） |
| **缺页处理** | 触发缺页异常，由操作系统处理 |
| **碎片问题** | 只有内部碎片，无外部碎片 |

### Q32：讲一下段表？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐（4星）**

**答案：**

**分段机制：**
- 虚拟地址分为4个段
- 每个段有独立的段表项
- 段表项记录段的基地址

**地址转换：**
```
物理地址 = 段基地址 + 段内偏移
```

**段表内容：**

| 内容 | 说明 |
|------|------|
| 段基地址 | 段在物理内存中的起始地址 |
| 段界限 | 段的大小 |
| 访问权限 | 读/写/执行权限 |

**与页表对比：**
- 页表：固定大小（4KB）
- 段表：可变大小
- 现代系统主要使用分页机制

### Q33：虚拟地址是怎么转化到物理地址的？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**转换过程：**

```
┌─────────────────────────────────────────────────────┐
│  1. CPU生成虚拟地址                                  │
│  2. MMU将虚拟地址拆分为页号和页内偏移                │
│  3. MMU查询页表，根据页号找到物理页号                │
│  4. 物理页号 + 页内偏移 = 物理地址                   │
│  5. 访问物理内存                                     │
└─────────────────────────────────────────────────────┘
```

**优化机制：**
- **TLB（快表）：** 缓存最近使用的页表项，加速查找
- **多级页表：** 减少页表占用的内存

**缺页处理：**
1. 虚拟地址在页表中查不到
2. 触发缺页异常（页错误中断）
-  缺页异常指的是CPU访问的虚拟地址在页表中查不到，触发MMU的页错误中断，和中断的处理流程相似，但是中断处理是硬件触发，而缺页异常是软件触发
-  和中断的区别是：
    - 中断是异步的，由外部设备触发
    - 缺页异常是同步的，由CPU访问无效地址触发
3. 操作系统分配物理内存
4. 更新页表
5. 返回用户空间继续执行

### Q34：程序的内存布局是怎么样的？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**用户空间内存布局（从低到高）：**

```
┌────────────────────────────────────────┐
│  保留区（不可访问）                     │ ← 防止野指针
├────────────────────────────────────────┤
│  代码段（.text）                       │ ← 二进制可执行代码
├────────────────────────────────────────┤
│  数据段（.data）                       │ ← 已初始化全局变量
├────────────────────────────────────────┤
│  BSS段（.bss）                         │ ← 未初始化全局变量
├────────────────────────────────────────┤
│  堆段（heap）                          │ ← 动态分配（向上增长）
├────────────────────────────────────────┤
│  文件映射段                            │ ← 动态库、共享内存
├────────────────────────────────────────┤
│  栈段（stack）                         │ ← 函数调用（向下增长）
└────────────────────────────────────────┘
```

**各段说明：**

| 段 | 存储内容 | 特点 |
|---|---------|------|
| 代码段 | 可执行指令 | 只读，不可修改 |
| 数据段 | 已初始化全局变量 | 静态分配 |
| BSS段 | 未初始化全局变量 | 静态分配，值为0 |
| 堆 | 动态分配内存 | 向上增长 |
| 栈 | 局部变量、函数调用 | 向下增长 |

### Q35：堆和栈的区别？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

| 维度 | 堆 | 栈 |
|------|---|---|
| **分配方式** | 动态（程序员手动） | 静态（编译器自动） |
| **内存管理** | 手动管理（malloc/free） | 自动管理（作用域） |
| **增长方向** | 向上（高地址） | 向下（低地址） |
| **大小** | 较大（受物理内存限制） | 较小（有限） |
| **速度** | 较慢 | 较快 |
| **碎片** | 可能有碎片 | 无碎片 |
| **分配失败** | 返回NULL | 抛出异常 |

### Q36：fork()会复制哪些东西？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**复制内容：**

1. **页表**（虚拟内存映射关系）
2. **文件描述符表**（打开的文件）
3. **信号处理方式**
4. **进程上下文**（寄存器状态等）

**不复制的内容（共享）：**
- 物理内存数据（写时复制）

**写时复制（Copy On Write）：**
- fork时不复制物理内存
- 父子进程共享物理内存
- 当任一进程写操作时，才复制物理内存

**优势：** 节省物理内存，减少fork时间

### Q37：介绍下Copy On Write（写时复制）？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**核心思想：** 写操作时才复制物理内存

**工作流程：**

```
1. fork()复制页表，指向相同物理内存
2. 页表项标记为只读
3. 父/子进程写操作时触发写保护中断
4. 操作系统复制物理内存
5. 更新页表，设置为可读写
6. 继续写操作
```

**节省的资源：**

| 资源 | 说明 |
|------|------|
| **物理内存** | 避免不必要的内存复制 |
| **时间** | fork操作更快速 |
| **CPU** | 减少复制开销 |

**应用场景：**
- fork()系统调用
- 写时复制的数据结构
- 内存映射文件的共享

### Q38：malloc 1KB和1MB有什么区别？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐⭐（6星）**

**答案：**

**分配方式差异：**

| 大小 | 分配方式 | 系统调用 |
|------|---------|---------|
| **< 128KB** | brk() | 调整堆顶指针 |
| **≥ 128KB** | mmap() | 文件映射区域分配 |

**具体差异：**

| 维度 | 小内存（brk） | 大内存（mmap） |
|------|-------------|---------------|
| **分配位置** | 堆区域 | 文件映射区域 |
| **释放方式** | free()归到堆 | 直接归还系统 |
| **碎片影响** | 可能产生碎片 | 无碎片问题 |
| **性能** | 较快 | 较慢（系统调用） |

**注意：** 不同glibc版本阈值可能不同

### Q39：介绍一下brk和mmap？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐⭐（6星）**

**答案：**

**brk()系统调用：**

```
作用：调整堆顶指针（break）
方式：通过移动堆顶指针获得新内存
适用：小内存分配（<128KB）
```

**mmap()系统调用：**

```
作用：在文件映射区域分配内存
方式：私有匿名映射
适用：大内存分配（≥128KB）
```

**对比图：**

```
堆区域（brk）
┌──────────────┐
│   已分配      │
├──────────────┤  ← brk()移动这个指针
│   未分配      │
├──────────────┤
│ 文件映射区域  │ ← mmap()分配
└──────────────┘
```

### Q40：操作系统内存不足的时候会发生什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**内存分配流程：**

```
┌─────────────────────────────────────────────────────┐
│  1. 应用程序请求内存                                  │
│  2. 访问虚拟地址 → 缺页中断                          │
│  3. 检查是否有空闲物理内存                            │
└─────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────┐
│  有空闲内存                                          │
│  → 直接分配，更新页表                                │
└─────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────┐
│  没有空闲内存                                        │
│  → 开始内存回收                                      │
└─────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────┐
│  回收方式：                                          │
│  - 后台回收（kswapd）：异步，不阻塞                  │
│  - 直接回收（direct reclaim）：同步，阻塞            │
└─────────────────────────────────────────────────────┘
           ↓
┌─────────────────────────────────────────────────────┐
│  回收后仍不足 → 触发OOM Killer                       │
│  → 选择占用内存高的进程杀死                          │
└─────────────────────────────────────────────────────┘
```

---

### Q41：哪些内存可以被回收？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐（5星）**

**答案：**

**两大类可回收内存：**

**1. 文件页（File-backed Page）**

| 特点 | 说明 |
|------|------|
| **来源** | 文件缓存、动态库 |
| **回收方式** | 直接释放或写回磁盘 |
| **干净页** | 直接释放内存 |
| **脏页** | 先写回磁盘，再释放 |

**2. 匿名页（Anonymous Page）**

| 特点 | 说明 |
|------|------|
| **来源** | 堆、栈等（无文件载体） |
| **回收方式** | Swap机制 |
| **过程** | 写入磁盘，释放内存 |
| **再次访问** | 从磁盘读入内存 |

**回收算法：** 基于LRU（最近最少使用）

**LRU链表：**
- **active list**：活跃内存页（最近访问）
- **inactive list**：不活跃内存页（很少访问）

### Q42：页面置换算法有哪些？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**5种常见算法：**

| 算法 | 简称 | 原理 | 特点 |
|------|------|------|------|
| **最佳置换** | OPT | 置换未来最长时间不访问的页面 | 理想状态，无法实现 |
| **先进先出** | FIFO | 置换最先进入内存的页面 | 实现简单，性能差 |
| **最近最久未使用** | LRU | 置换最长时间未使用的页面 | 近似最优，开销大 |
| **时钟置换** | Clock | 类似LRU，但用环形链表实现 | 折中方案，常用 |
| **最不常用** | LFU | 置换访问次数最少的页面 | 考虑频率，忽略时间 |

**性能对比（缺页次数）：**
- OPT：最少（理想）
- LRU：较少
- Clock：中等
- FIFO：较多

## 7. 中断

### Q43：什么是中断？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（7星）**

**答案：**

**定义：** CPU暂停当前任务，处理其他事情，处理完后继续执行

**中断分类：**

| 大类 | 子类 | 说明 |
|------|------|------|
| **外部中断** | 可屏蔽中断（INTR） | 来自外设，可屏蔽 |
| | 不可屏蔽中断（NMI） | 硬件故障，不可屏蔽 |
| **内部中断** | 软中断 | 软件主动发起（系统调用） |
| | 异常 | 指令执行错误（除0、缺页） |

**中断的作用：**
- 提高CPU效率（不必轮询）
- 及时响应紧急事件
- 实现异步处理

---

### Q44：中断的流程是怎样的？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐⭐（6星）**

**答案：**

**中断处理流程：**

```
1. 发生中断
   ↓
2. CPU响应中断（保存现场）
   ↓
3. 查找中断向量表，获取处理程序地址
   ↓
4. 执行中断处理程序
   ↓
5. 恢复现场，返回原程序
```

**关键步骤说明：**

| 步骤 | 操作 |
|------|------|
| 保存现场 | 保存PC、寄存器状态 |
| 查找向量表 | 根据中断号找到处理程序 |
| 执行处理 | 处理中断事件 |
| 恢复现场 | 恢复之前保存的状态 |
| 返回继续 | 跳转到原程序继续执行 |

---

### Q45：中断的类型有哪些？

**掌握程度：⭐⭐⭐⭐（8星）**
**考察频次：⭐⭐⭐（5星）**

**答案：**

**按事件来源分类：**

```
┌─────────────────────────────────────────────────────┐
│                    中断                              │
├────────────────────┬────────────────────────────────┤
│     外部中断        │            内部中断             │
├────────────────────┼────────────────────────────────┤
│ 可屏蔽中断（INTR） │   软中断（系统调用）            │
│ 不可屏蔽中断（NMI）│   异常（除0、缺页等）           │
└────────────────────┴────────────────────────────────┘
```

**详细说明：**

| 类型 | 来源 | 特点 | 示例 |
|------|------|------|------|
| 可屏蔽中断 | 外设 | 可被IF位屏蔽 | 硬盘、网卡 |
| 不可屏蔽中断 | 硬件 | 无法屏蔽 | 电源故障 |
| 软中断 | 软件 | 系统调用 | int 0x80 |
| 异常 | CPU | 执行错误 | 除0、越界 |

## 8. 网络IO

### Q46：你了解过哪些IO模型？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**5种IO模型：**

| 模型 | 特点 | 阻塞情况 |
|------|------|---------|
| **阻塞IO** | 发起IO后等待完成 | 整个过程阻塞 |
| **非阻塞IO** | 发起IO后立即返回 | 需轮询检查 |
| **IO多路复用** | 等待多个IO事件 | 单线程监听多个 |
| **信号驱动IO** | IO完成时发信号通知 | 异步通知 |
| **异步IO** | 发起IO后做其他事 | 完全不阻塞 |

**各模型对比：**

```
阻塞程度从高到低：
阻塞IO → 非阻塞IO → IO多路复用 → 信号驱动IO → 异步IO
```

---

### Q47：服务器处理并发请求有哪几种方式？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**3种主要方式：**

**1. 多进程/多线程**

```
特点：每个请求一个进程/线程
优点：简单
缺点：并发数受限于系统资源
```

**2. IO多路复用**

```
特点：一个线程监听多个socket
优点：资源复用，高并发
代表：select、poll、epoll
```

**3. 多路复用+多线程（混合模式）**

```
特点：多个进程，每个进程多个线程
优点：结合两者优势
代表：Nginx、Netty
```

---

### Q48：讲一下IO多路复用？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

**核心概念：** 复用一个线程，处理多个socket事件

**解决的问题：**
- 单线程处理多连接
- 避免创建过多线程
- 减少上下文切换开销

**工作原理：**

```
┌─────────────────────────────────────────────────────┐
│  IO多路复用接口（select/poll/epoll）                │
│         ↓                                           │
│  内核监听多个socket                                 │
│         ↓                                           │
│  有事件发生时通知应用程序                           │
│         ↓                                           │
│  应用程序处理就绪的socket                           │
└─────────────────────────────────────────────────────┘
```

**优势：**
- 单线程支持高并发
- 减少线程创建和切换开销
- 适合C10K问题

---

### Q49：select、poll、epoll的区别是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（10星）**

**答案：**

**三者对比：**

| 维度 | select | poll | epoll |
|------|--------|------|-------|
| **数据结构** | BitsMap | 动态数组 | 红黑树 + 链表 |
| **最大连接数** | 1024 | 受限于fd | 受限于系统fd | fd是文件描述符，每个进程默认打开1024个文件描述符
| **时间复杂度** | O(n) | O(n) | O(1) |
| **内存拷贝** | 2次拷贝 | 2次拷贝 | 1次拷贝 |
| **工作方式** | 轮询 | 轮询 | 回调通知 |

**epoll的优势：**

1. **高效数据结构**
   - 红黑树管理待检测socket
   - 链表记录就绪事件

2. **减少拷贝**
   - 只在epoll_ctl时拷贝
   - epoll_wait不拷贝

3. **事件驱动**
   - 只返回就绪的socket
   - 无需遍历所有socket

**epoll被称为解决C10K问题的利器**

### Q50：epoll的边缘触发和水平触发有什么区别？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**
水平触发是指在socket状态没有改变时，epoll_wait会不断通知应用程序。
边缘触发是指在socket状态发生改变时，epoll_wait才会通知应用程序。
epoll_wait是指等待就绪事件发生，返回就绪的socket列表。
**触发模式对比：**

| 维度 | 水平触发（LT） | 边缘触发（ET） |
|------|---------------|---------------|
| **触发条件** | 满足条件就通知 | 状态变化才通知 |
| **通知次数** | 可能多次 | 只有一次 |
| **数据处理** | 可分批处理 | 需一次读完 |
| **编程复杂度** | 简单 | 复杂 |

**比喻说明：**

| 模式 | 比喻 |
|------|------|
| **水平触发（LT）** | 快递箱不停发短信，直到取出快递 |
| **边缘触发（ET）** | 只发一次短信提醒 |

**使用建议：**

| 触发模式 | 适用场景 | 搭配使用 |
|----------|---------|---------|
| **LT** | 简单场景 | 阻塞/非阻塞IO |
| **ET** | 高性能场景 | 非阻塞IO + 循环读取 |

**性能：** ET > LT（减少epoll_wait调用次数）

### Q51：什么是零拷贝？

**掌握程度：⭐⭐⭐⭐⭐（10星）**
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

**传统IO的数据拷贝：**

```
用户空间 ↔ 内核空间（2次CPU拷贝）
内核空间 ↔ 磁盘/网卡（2次DMA拷贝）
共4次上下文切换，4次数据拷贝
```

**零拷贝优化：**

```
通过sendfile()系统调用
只发生2次上下文切换，2次数据拷贝
数据在内核中完成传输
```

**零拷贝的改进：**

| 维度 | 传统IO | 零拷贝 |
|------|-------|-------|
| **上下文切换** | 4次 | 2次 |
| **数据拷贝** | 4次 | 2次 |
| **CPU参与** | 2次（用户态-内核态） | 0次（纯DMA） |
| **系统调用** | 多次 | 1次（sendfile） |

**适用场景：**
- 文件传输
- 日志处理
- 消息队列
