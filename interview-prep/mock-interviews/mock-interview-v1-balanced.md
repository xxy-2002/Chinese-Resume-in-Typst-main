# 模拟面试稿 V1：均衡版

这版模拟稿适合 `AI应用研发工程师` 常规技术一面，问题覆盖技能、实习、项目和基础知识，弱化教育。

## 1. 自我介绍一下

答题主线：

- 教育背景
- 当前方向
- 三段最重要经历

示例回答：

“我最近几段经历比较集中在 Agent 和大模型应用工程上。实习里，一段是在京东做 JoyDeliver 交付智能平台，主要做 Harness Agent、Runtime 和 Skill/Pipeline 编排；另一段是在 Moatable 做 Flow 智能体平台，涉及多模型接入、记忆、路由、评估和成本优化。项目上我做了一个 Skill Factory，重点是把 Skill 的生产、测评、优化和发布做成闭环。我比较想做的是把 Agent 真正落进业务流程，做成可评测、可观测、可持续优化的系统。”

- 这三段经历里你最想展开哪一段

横向追问：

- 这些经历之间的共通点是什么

## 2. 你在京东做的 JoyDeliver 是什么

答：

“它本质上是一个面向 ToB 交付流程的智能平台，不是单一问答 Agent。它把需求定义、原型、方案、开发、测试这些环节组织成结构化任务流。我主要做了两层，一层是底层 Harness Agent 和 Runtime，负责执行、工具调用、状态流转、上下文和 trace；另一层是基于 Skill 的 Pipeline 编排，让交付经验能复用。”

纵向追问：

- Runtime 管什么
- Skill 和 Pipeline 为什么都要抽象出来
- 你们怎么做 trace

横向追问：

- 它和 Dify / Coze / LangGraph 有什么差别

## 3. 你在 Flow 里最有代表性的工作是什么

答：

“我觉得最有代表性的是三块。第一是多模型适配，用 Model Adapter 接 Gemini 和 Bedrock(Qwen)，把底层模型差异收敛起来；第二是记忆中枢 Cortex，支持单 Agent 和多 Agent 的记忆共享与逻辑隔离；第三是评估和成本优化，做了自动化评估流水线，还做了 TOON 序列化和语义压缩来降 token 消耗。”

## 4. Skill Factory 想解决什么问题

答：

“它想解决的问题是：Skill 不能只靠手工改 prompt，而是要像工程对象一样被生产、评估、优化、回归和发布。核心是用可插拔 Harness 统一 Executor、Evaluator、Optimizer，再基于 case、trace 和指标去生成候选、筛选候选、做回归和发布门禁。”

纵向追问：

- Harness 为什么要可插拔
- GEPA 怎么落地
- 为什么要保留 trace

横向追问：

- 它和普通 prompt 优化工具有什么区别

## 5. 你怎么理解 Harness

答：

“我理解 Harness 是 agent 的执行底座。模型只是其中一个部分，Harness 负责把工具、上下文、工作区、状态、评测、trace 和安全规则组织起来，让 agent 真正能稳定执行。”

纵向追问：

- 它和 Runtime 的区别是什么

横向追问：

- 为什么 2026 大家更爱讲 Harness

## 6. Redis 分布式锁你怎么理解

答：

“Redis 分布式锁适合做跨进程或跨实例的轻量并发协调。核心是原子加锁、过期时间和安全释放。在我的项目语境里，它主要用于高并发下的共享资源竞争控制，比如多 Agent 记忆写入和缓冲协同。”

纵向追问：

- 为什么要配 Lua
- 有什么坑

横向追问：

## 7. MySQL 索引你最常讲什么

“我一般会先讲索引分类，然后重点讲联合索引、最左前缀、回表和覆盖索引，因为这几块最容易和真实查询优化场景结合。”

## 8. TCP 三次握手为什么不是两次

答：

“因为不仅要让客户端知道自己能发能收，也要让服务端确认双方的发送和接收能力都正常。三次握手本质上是在同步双方的初始序列号并确认双向通信能力。”

## 9. 你怎么看 Skill 和 Prompt 的区别

答：

“Prompt 更像一次性说法，Skill 是把经验封装成可复用能力单元，通常还带规则、参考资料、脚本和执行边界。”

## 10. Hook 在 Agent 里是做什么的

答：

“Hook 是挂在 agent 生命周期某个节点上的可插拔逻辑。它常用于安全拦截、上下文补充、日志审计、工具调用治理或者失败后的补偿动作。对平台型 Agent 来说，hook 很重要，因为它能在不改主流程的前提下增强治理能力。”
