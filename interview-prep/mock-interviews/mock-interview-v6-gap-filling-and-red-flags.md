# 模拟面试稿 V6：查漏补缺与红旗追问版

这版专门模拟面试官发现你“会说大词”之后的继续下压，重点是识别你最容易被问穿的点。

## 1. 你说自己做过 Agent 平台，那你到底写过多少“平台代码”，多少“业务 glue code”？

答题重点：

- 不要回避
- 区分抽象层和落地层
- 说清自己在平台中的真实负责范围

## 2. 你一直说 Trace 很重要，那给一个没有 Trace 就难以排查的问题例子

答题重点：

- 路由错
- 工具参数错
- 上下文污染

## 3. 你写了很多概念，哪些是你真正做过的，哪些是你通过相关工作学习到的？

答题重点：

- JoyDeliver / Flow / Skill Factory 是你主线
- aboutskill / GenericAgent / Meta-Harness 是外部参考

## 4. 你说 GEPA 很适合 Skill，为什么？

答题重点：

- 多目标
- 候选生成
- Pareto
- trace 驱动

## 5. 你说 Tool Use、MCP、ACP 都知道，那它们什么时候会在一个系统里同时出现？

答题重点：

- Agent 接工具
- Agent 和 Agent 协作
- 统一执行和通信层

## 6. 你如果只保留一个项目讲，会讲哪个？

答题重点：

- Skill Factory
- 或者 JoyDeliver

但要能解释为什么

## 7. 你如果只保留一个基础知识主题讲，会讲哪个？

答题重点：

- Redis 或 MySQL

因为最容易和项目经历挂钩

## 8. 面试官如果说“你这些东西听着都像框架词，业务价值是什么”，你怎么答？

答题重点：

- 提升任务完成率
- 降低成本
- 提高复用性
- 提高可评测性

## 9. 你如果被问到“为什么不是直接用现成平台”，你怎么答？

答题重点：

- 平台抽象层次不够匹配
- 业务流程特殊
- 需要更强可观测性或治理能力
