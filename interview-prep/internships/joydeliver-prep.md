## 三、推荐表达

可以按下面的顺序讲：

“JoyDeliver 本质上是一个面向 ToB 项目交付流程的智能平台。我们面对的问题不是单轮问答，而是交付材料分散、需求经常变化、上下文容易断、历史经验难复用。所以平台不是做一个单一 Agent，而是把需求、原型、方案、开发、测试这些环节组织成结构化任务流。我的工作主要集中在两层，一层是底层 `Harness Agent + Runtime`，负责执行、工具调用、上下文传递、状态流转、异常处理和 trace；另一层是上层基于 `Skill` 的 `Pipeline` 编排，把不同业务节点组合成可复用交付流水线。” 

## 四、面试官可能会追问

- 为什么要抽象 `Skill`
- `Pipeline` 和普通工作流的区别是什么
- `Runtime` 具体管什么
- 如何做状态流转和异常处理
- trace 记录了哪些东西
- 多个 Agent 之间怎么传递上下文
- 你们怎么保证结果质量
- 平台和 Dify / Coze / LangGraph 这类东西的区别是什么

## 五、简单回答方向

- `Skill`：
  代表可复用能力单元，便于沉淀经验和组合复用

- `Pipeline`：
  代表业务流程级编排，不只是工具链调用，而是面向交付节点的任务组织

- `Runtime`：
  管执行生命周期、工具调用、上下文、状态、异常和 trace

- `Trace`：
  主要用于可观测性、失败复现和链路诊断
