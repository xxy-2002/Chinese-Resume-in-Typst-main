## 1. 大模型应用基础

### Q1：SFT 是什么？它解决什么问题？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

SFT（监督微调）是在预训练模型基础上，用高质量“指令-回答”数据继续训练，让模型从“会生成语言”变成“更会遵循指令、完成任务”的助手模型。

**一句话表达：**

“SFT 解决的是模型‘会说话但不一定会按要求做事’的问题。”

**和你项目的连接：**

- 你简历技能栏里已经写了 `SFT`
- 在 Agent 应用场景里，SFT 更多是让模型学会任务格式、工具调用习惯和业务表达

---

### Q2：LoRA 为什么适合工程实践？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

LoRA 是一种参数高效微调方法。它冻结大部分基座参数，只训练少量低秩增量矩阵。

优点：

- 显存占用更低
- 训练成本更低
- 更容易做多版本适配
- 部署时可插拔

**一句话表达：**

“LoRA 的价值是用更低的成本做可控微调。”

---

### Q3：DPO、RLHF、GRPO 之间怎么区分？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

- `RLHF`：更完整的强化学习对齐流程，通常包含奖励模型和策略优化
- `DPO`：直接用偏好对做优化，不一定需要完整 PPO 流程
- `GRPO`：更偏高效、轻量的策略优化方式，常出现在推理或 Agent 相关训练语境里

**一句话表达：**

“DPO 更像偏好优化的简化路径，RLHF 更完整，GRPO 更偏效率导向的策略更新。”

---

### Q4：为什么当前岗位不需要把大模型底座细节讲太深？

**掌握程度：⭐⭐⭐⭐（8星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

因为这个岗位更像“AI 应用研发”，核心不在于你能推多少底层模型论文，而在于你能不能把模型接进业务流程，做出可用、可评测、可迭代的系统。

**一句话表达：**

“这个岗位更关心模型怎么落到业务里，而不是只关心底座模型怎么训练出来。”

## 2. Agent 开发核心

### Q5：什么是 Agent？和普通 Prompt 有什么区别？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（10星）**

**答案：**

Agent 是围绕目标持续做决策、调用工具、读写上下文并执行多步任务的系统。

区别：

- Prompt 更像一次性请求
- Agent 更像带执行闭环的任务系统

**一句话表达：**

“Prompt 负责说一次，Agent 负责把事情做完。”

---

### Q6：什么是 Harness？为什么 2026 大家更爱讲 Harness？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

Harness 可以理解成 Agent 的执行底座。它负责把工具、上下文、状态、工作区、权限、评测和可观测性组织起来。

2026 大家更爱讲它，是因为现在越来越清楚：

> Agent 是否稳定，往往不是模型本身决定的，而是模型外面的执行基座决定的。

**和你项目的连接：**

- `JoyDeliver`：`Harness Agent + Runtime`
- `Skill Factory`：可插拔 `Harness`

---

### Q7：什么是 Skill？它和 Tool 的区别是什么？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

Skill 是可复用能力单元，通常包含任务说明、规则、参考资料和必要脚本。  
Tool 更偏单个可调用能力，如一个 API 或一个函数。

**一句话表达：**

“Tool 是一个能力点，Skill 是一整套可复用做事方式。”

---

### Q8：什么是 Hook？

**掌握程度：⭐⭐⭐⭐⭐（8星）**  
**考察频次：⭐⭐⭐⭐（7星）**

**答案：**

Hook 是挂在 Agent 生命周期某个节点上的可插拔逻辑，常用于：

- 安全拦截
- 上下文补充
- 审计日志
- 工具调用治理

**一句话表达：**

“Hook 是 Agent 生命周期上的治理接口。”

---

### Q9：什么是 Agentic Workflow？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

Agentic Workflow 是把传统固定流程和 Agent 决策能力结合起来的工作流。

- 固定部分保证稳定
- 动态部分让模型按上下文决策

**一句话表达：**

“Agentic Workflow 不是全靠模型自由发挥，而是固定流程和动态决策结合。”

---

### Q10：Multi-Agent 为什么不是简单多开几个模型？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

因为多智能体的难点在于：

- 角色分工
- 路由稳定性
- 上下文同步
- 状态共享
- 成本控制

真正的多 Agent 是协作系统，不是并排放几个模型。

## 3. RAG、记忆与工具接入

### Q11：RAG 的核心流程是什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

RAG 的核心流程通常是：

1. Query 处理
2. 检索召回
3. 重排
4. 上下文构建
5. 生成回答

**一句话表达：**

“RAG 的本质是先找证据，再让模型基于证据回答。”

---

### Q12：Memory 为什么不能只靠上下文窗口？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

因为上下文窗口有长度限制，而且所有信息都塞进去会带来：

- 成本上升
- 噪声增加
- 早期重要信息被淹没

所以 Agent 往往要把记忆分成：

- 短期记忆
- 长期记忆
- 工作记忆

---

### Q13：MCP 是什么？和普通 Tool Calling 的区别是什么？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

MCP（Model Context Protocol）可以理解成模型和外部能力之间的标准化接入协议。

区别：

- Tool Calling 更像“调一个工具”
- MCP 更像“用统一协议接一类能力”

**一句话表达：**

“Tool Calling 解决单点调用，MCP 解决标准化接入。”

---

### Q14：SSE 为什么在 AI 应用里常见？

**掌握程度：⭐⭐⭐⭐⭐（8星）**  
**考察频次：⭐⭐⭐⭐（7星）**

**答案：**

SSE 是基于 HTTP 的单向流式推送机制，很适合：

- 模型增量输出
- 状态事件展示
- 流式回答

它比 WebSocket 更轻，特别适合“服务端持续输出，客户端边收边展示”的场景。

## 4. 部署、评测与生产设计

### Q15：什么是 Trace？为什么重要？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（9星）**

**答案：**

Trace 是一次 Agent 执行过程的可观测记录，记录的不只是结果，还包括：

- 模型输出
- 工具调用
- 中间状态
- handoff
- 错误与重试

它重要的原因是：

- 失败能复现
- 优化有证据
- 回归可对比

**一句话表达：**

“没有 trace，很多 Agent 优化都在拍脑袋。”

---

### Q16：什么是 Eval？为什么 Agent 场景里更难？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

Eval 是用一套可重复方法判断系统是否真的变好了。

Agent 场景更难，是因为它常常不只是评最终答案，还要评：

- 工具是否用对
- 路径是否走对
- 成本是否可控
- 回归有没有坏

**一句话表达：**

“Agent Eval 评的不是一句话，而是一整条执行链路。”

---

### Q17：vLLM 为什么快？

**掌握程度：⭐⭐⭐⭐⭐（9星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

vLLM 的核心优势通常来自：

- 更高效的 KV Cache 管理
- `PagedAttention`
- 连续批处理
- 前缀缓存

**一句话表达：**

“vLLM 的价值不只是快，而是能更高效地把推理吞吐和显存利用率做起来。”

---

### Q18：生产环境里的 Agent 系统最需要关注什么？

**掌握程度：⭐⭐⭐⭐⭐（10星）**  
**考察频次：⭐⭐⭐⭐⭐（8星）**

**答案：**

最关键的是：

- 稳定性
- 可观测性
- 成本
- 延迟
- 限流与重试
- 安全与权限
- 回归与评测

**和你项目的连接：**

- `JoyDeliver`：Runtime、Trace、Pipeline
- `Flow`：评估流水线、成本优化、记忆与治理
- `Skill Factory`：评测闭环、trace、发布门禁
