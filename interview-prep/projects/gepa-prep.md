# GEPA 面试准备

这份文档服务于 `Skill Factory` 项目中的 `GEPA` 表述，目标不是做论文综述，而是让你能把它讲清楚、讲到工程上。

## 一、在你的项目里，GEPA 应该怎么讲

先讲工程视角，不要先讲论文名词。

推荐定义：

“我在项目里把 GEPA 理解成一种候选生成与多目标选优方法。它不是只改一次 prompt 然后凭感觉判断，而是基于执行轨迹和失败 case 生成多个候选，再按多个目标去选出更优版本。”

一句话版本：

“GEPA 帮我把 Skill 优化从‘手工调 prompt’变成‘基于轨迹生成候选，再做多目标筛选’。”

## 二、GEPA 里最值得讲的两个词

### 1. Genetic

在你的项目语境里，`Genetic` 不必讲得像标准遗传算法课本，而是强调：

- 从已有候选出发继续变异
- 保留有效模式
- 不断试新改法

可以这样说：

“Genetic 这一层可以理解成对候选进行持续变异和迭代，不断从已有成功模式里扩展出新方案。”

### 2. Pareto

这是面试里很加分的点。

可以这样说：

“Pareto 的价值是避免只看单一指标。Skill 优化不能只追求成功率，还要看成本、稳定性、泛化和回归风险，所以我会保留多目标下的优势候选，而不是只留一个总分最高的版本。”

## 三、GEPA 在 Skill Factory 里的落地链路

建议讲成 5 步：

1. 从真实 `case` 和执行 `trace` 中发现失败模式
2. 针对失败模式生成新的 `prompt / spec / code` 候选
3. 用统一 `Harness` 执行候选
4. 用评测集和指标体系评估候选
5. 用 `Pareto Frontier` 保留多目标下占优的版本

推荐表达：

“GEPA 在我的项目里不是独立模块，而是闭环中的候选优化方法。前面靠 case 和 trace 找问题，中间靠候选生成做改动，后面靠评测和 Pareto 筛选保留更优方案。”

## 四、为什么不用普通 prompt 调优

这是高频追问。

答法：

“普通 prompt 调优的问题是，很多时候只改一个版本，然后人工比较一下，缺少系统性。GEPA 这种思路更适合 Skill，因为 Skill 的问题往往不是单一输出风格，而是任务完成率、工具调用正确性、稳定性和成本的综合问题。”

## 五、为什么要配 Trace 一起讲

GEPA 单独讲不够，最好和 `trace` 连起来讲。

可讲法：

“候选生成不能拍脑袋做，所以我会把 trace 放在前面。先看具体失败轨迹，再决定改什么候选。这样 GEPA 不是盲目搜索，而是基于证据做定向优化。”

## 六、为什么要配 Pareto 一起讲

如果面试官问：

- 为什么不用一个总分
- 为什么不用简单排序

可以这样说：

“因为 Skill 在真实场景下是多目标优化问题。一个候选可能成功率更高，但 token 成本更高；另一个候选可能更稳定，但稍慢一点。如果只看一个总分，很容易把有价值的候选过早丢掉，所以用 Pareto 保留多目标下占优的版本更合理。”

## 七、面试官可能会追问

- 你说的 GEPA 和普通遗传算法有什么区别
- 候选是怎么生成的
- 为什么要同时改 `prompt / spec / code`
- 什么情况下会选择保留多个候选
- Pareto Frontier 具体怎么理解
- 多目标指标通常有哪些

## 八、简单回答方向

- `候选生成`：
  可以围绕 prompt、spec、code 三类对象做

- `候选评估`：
  不只看最终正确率，也看稳定性、成本和回归

- `Pareto Frontier`：
  保留“在至少一个维度更优，且在其他维度不被完全支配”的版本

- `trace 驱动`：
  让候选生成更定向，而不是盲调

## 九、和岗位的连接方式

面向 `AI应用研发工程师 / 商业智能&决策支持` 岗位时，GEPA 最好不要讲成算法炫技，而是讲成：

- 结构化任务优化方法
- 多目标选优方法
- 业务 Agent 持续优化方法

一句话收口：

“我觉得 GEPA 的价值不在于名字，而在于它很适合业务 Agent 这种多目标、强流程、强评测依赖的优化场景。”

## 十、面试前简单回看

- 能一句话解释 `GEPA`
- 能一句话解释 `Pareto Frontier`
- 能说清楚 GEPA 在你的项目里是怎么接进闭环的
- 能回答为什么它比手工 prompt 调优更适合 Skill
